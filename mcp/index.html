Write Ottid recipes from Claude Desktop

ottid-mcp is a small program that lets Claude Desktop, or any other MCP host, read, validate and save Ottid recipes. You describe the workflow in chat; Claude drafts the recipe and checks it against Ottid's own validator before it is written to disk.

Check your edition first. Ottid is built in two editions from the same source. The free, dictation-only edition is the one every public release so far has shipped. It does not contain ottid-mcp or the Recipes section: command mode, recipes and MCP are compiled out of it, not just hidden.

They belong to the full edition, which for now you build from source (GPL-3.0). No installer includes ottid-mcp yet, so there is nothing to download. You build the binary yourself, as shown below. A packaged full edition has not been released.

What it is

A recipe is a recipe.yaml file: a named desktop workflow with parameters and phrases, in Hebrew and English, that trigger it. In the full edition you run one from the Hub or by voice in command mode. Writing the YAML by hand is fiddly, so Ottid offers its recipe handling over the Model Context Protocol and lets an agent do the drafting.

The Hub has no MCP settings tab yet, so you wire it up by hand, as described below. Claude Desktop starts ottid-mcp as a child process and talks to it over stdin and stdout (the stdio transport).

For reference, this is a real starter recipe, abridged:

id: lock-workstation
name: Lock the workstation
description: Lock the session immediately (Win+L on Windows).
intents:
  - "lock the screen"
  - "lock my computer"
  - "נעל את המחשב"
parameters: []
permissions:
  - keyboard.type
os_steps:
  windows:
    - type: key_chord
      keys: [Meta, L]

The five tools

The tool names are plain snake_case, with no ottid. prefix. MCP hosts normally show them grouped under the name you give the server in the config.

list_recipes
Lists every installed recipe, both bundled starters and your own, as a JSON array of id, description, source (starter or user) and path. Arguments: none.
get_recipe
Returns the full recipe.yaml for one recipe. If you have saved a recipe with the same id as a starter, yours wins. Arguments: id (string).
validate_recipe
Checks a draft against the recipe schema and answers ok or a list of every problem found, so Claude can fix them in one round. Arguments: yaml (string).
save_recipe
Validates a draft and, only if it passes, writes it to your recipes folder. The id must match the id: inside the YAML. It refuses to replace an existing recipe unless overwrite is true. Arguments: id (string), yaml (string), overwrite (optional boolean, default false).
list_recipe_step_types
Returns the JSON Schema of every step type the recipe runtime supports, so Claude learns the vocabulary before drafting. Arguments: none.

All five only read or write recipe.yaml files. None of them runs a recipe, presses a key, clicks, opens a file or starts a program. A saved recipe does nothing until you trigger it from the Hub or by voice.

Set it up

  1. Build the binary. Get the source and, from the repository root, run: 
    cargo build --release -p ottid-core --bin ottid-mcp

    You need the Rust toolchain; the repository pins its version in rust-toolchain.toml. Build with the default features: the binary is part of command mode, so --no-default-features leaves it out. The result is target/release/ottid-mcp.exe on Windows, or target/release/ottid-mcp elsewhere.

  2. Open Claude Desktop's config file:
    OSPath
    Windows%APPDATA%\Claude\claude_desktop_config.json
    macOS~/Library/Application Support/Claude/claude_desktop_config.json
  3. Add Ottid under mcpServers. If you already have other servers there, add ottid next to them. Use the real paths from your machine; forward slashes work on Windows too. 
    {
  "mcpServers": {
    "ottid": {
      "command": "C:/path/to/ottid/target/release/ottid-mcp.exe",
      "env": {
        "OTTID_BUNDLED_RECIPES_DIR": "C:/path/to/ottid/recipes/starters"
      }
    }
  }
}

    OTTID_BUNDLED_RECIPES_DIR tells the server where the starter recipes are. Without it the server falls back to the recipes/starters folder of the checkout it was built in, which only works while that checkout stays where it was.

  4. Restart Claude Desktop completely, so it reads the new config and starts the server.
  5. Try it. Ask: "List my Ottid recipes." Claude should call list_recipes and show the bundled starters. Then ask for something new, for example "Write me an Ottid recipe that opens my notes app." Claude can look up the step vocabulary with list_recipe_step_types, draft the YAML, run it through validate_recipe and finish with save_recipe.

Where your recipes are saved

save_recipe writes <id>/recipe.yaml inside the per-user recipes folder:

OSPath
Windows%LOCALAPPDATA%\ottid\recipes\
macOS~/Library/Application Support/ottid/recipes/
Linux$XDG_DATA_HOME/ottid/recipes/ (or ~/.local/share/ottid/recipes/)

Set OTTID_USER_RECIPES_DIR in the same env block to use another folder. The Hub's Recipes section in a full-edition build reads the same folder.

Privacy and trust

  • No network port. ottid-mcp listens for nothing. It answers only over the pipes of the program that started it, and only that program can talk to it.
  • No audio, no transcripts. The server never touches your dictation. It handles recipe files and nothing else.
  • Claude Desktop is a cloud app. Whatever Claude reads through these tools, such as recipe text or the on-disk path that list_recipes reports, becomes part of your conversation with Claude and is handled under its terms. Ottid itself stays local.
  • Only point a host at a binary you built or trust. The host runs whatever the command field names.

Moving over from Lashon

Ottid used to be called Lashon. If you wired lashon-mcp into an MCP host, change these:

  • The binary. Point command at ottid-mcp instead of lashon-mcp, rebuilt from the current source.
  • The environment variables. LASHON_* became OTTID_*, so LASHON_BUNDLED_RECIPES_DIR is now OTTID_BUNDLED_RECIPES_DIR.
  • The server name. The key under mcpServers is only a label you choose. Renaming lashon to ottid is optional but keeps things readable.
  • The tool names stay the same. They were plain snake_case before the rename and still are.
  • Your recipes move on their own. They used to live in a lashon/recipes folder next to the new ottid one. A release build, such as the one above, moves them across the first time it needs the folder. Debug builds leave the old folder alone unless OTTID_ADOPT_LEGACY=1 is set.

If it doesn't show up

No Ottid tools in Claude. Check that the config is valid JSON, that command points at the real file, and that you fully restarted Claude Desktop. You can also run ottid-mcp by hand in a terminal: it starts, logs starting ottid-mcp and then waits quietly for a host.

Claude lists no starters. Set OTTID_BUNDLED_RECIPES_DIR to your checkout's recipes/starters folder.

You want more detail. The server logs to stderr, never stdout, because stdout carries the protocol. Add "RUST_LOG": "debug" to the env block for more output.
